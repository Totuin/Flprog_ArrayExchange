# Flprog_ArrayExchange 0.1.1 — внутренний буфер транзакции

Библиотека Arduino для двустороннего обмена массивами через существующий `FlprogAbstractUartExecutor` (`Flprog_Utilites`), независимо от способа хранения. Поддерживаются bool, int16_t, String. Адаптеру передаются ID (`uint16_t`), размер (`uint16_t`), указатели на функции `T read(uint16_t index)` и `void write(T value, uint16_t index)`. Сам массив не передаётся. Для чтения или записи можно передать `nullptr`, запрещая это направление. Индексы элементов начинаются с 0. ID должны быть уникальны. Объекты, массив указателей, имена (const char*) должны жить всё время работы библиотеки. Изменять их только из основного цикла, не из ISR.

## Подключение

Распаковать папку `Flprog_ArrayExchange` в `sketchbook/libraries`. Зависимость: существующая `Flprog_Utilites` и её обычные зависимости (RT_HW). Не заменяет и не изменяет их. Заголовок `flprogArrayExchange.h`. Пример `examples/ArrayExchangeDemo` с тремя массивами RAM. В FLProg используются его готовые функции доступа. `setUart(&FLProgUart, number)`, `setArrays(arrays, count)`, `setWriteEnable(true)` (по умолчанию false), затем `pool()` в основном цикле. UART должен быть выделен обмену: не смешивать с логами или другими обработчиками. Не менять порт во время транзакции.

Для приложения автоматики разрешение записи задавать в каждом цикле **до** `pool()`, только в безопасном остановленном состоянии. `setWriteEnable(false)` сбрасывает отложенную транзакцию. `setWriteEnable` существует и у отдельного адаптера. Можно задавать независимые границы `setLimits(min,max)` для int16_t; по умолчанию весь диапазон int16_t. `setMaxLength(bytes)` для String: по умолчанию 64 байта, не символа; при использовании EEPROM уменьшить в соответствии с фактической ёмкостью элемента. `setName` задаёт имя массива (до 32 байт UTF-8). Не полагаться на ограничения приложения Windows: проверка на контроллере обязательна. В автоклаве рецепты не заменяют независимую аппаратную защиту; безопасные рабочие пределы и пищевые режимы должны быть определены отдельно.

## Протокол v1

ASCII, одна команда на строку, LF (CRLF также допустим). Поля через `;`. Суффикс `*HHHH` — CRC-16/CCITT-FALSE (poly 1021, init FFFF, без отражения, xorout 0000; `123456789` → `29B1`) от ASCII перед `*`, четыре шестнадцатеричных цифры. Обязателен для BEGIN/SET/COMMIT/CANCEL; необязателен для запросов только чтения (для теста через монитор). Все ответы содержат CRC и LF. Строки и имена: UTF-8 в HEX (без пробелов), пустая строка = пустое поле. bool: 0/1. int16_t: десятичное целое со знаком минус при необходимости. Не принимать мусор, переполнение, недопустимые индексы, некорректный UTF-8. Поддержка одной команды в полёте: дождаться полного ответа перед следующей. Встроенный RX максимум 191 байт до LF, включая CRC и возможный CR.

| Запрос (до CRC) | Ответ (до CRC) |
|---|---|
| `PING` | `OK;PONG` |
| `INFO` | `OK;INFO;версия;количество_массивов;max_string_bytes;staging_bytes;max_items;write_enable` |
| `DESCRIBE;slot` | `OK;ARRAY;id;type;size;flags;max_string_length;name_hex` |
| `GET;id;index` | `OK;VALUE;id;index;value` |
| `BEGIN;items` | `OK;BEGIN;items` |
| `SET;id;index;value` | `OK;SET;id;index` |
| `COMMIT` | `OK;APPLIED;items` |
| `CANCEL` | `OK;CANCELLED` |

slot — порядковый номер адаптера от 0; type: 1=bool, 2=int16, 3=String; flags: бит 0 — чтение, бит 1 — запись (с учётом текущего разрешения). max_string_length=0 для числовых типов. INFO сообщает общие лимиты. Ошибки `ERROR;код`, например CRC, CRC_REQUIRED, VALUE, INDEX, BUFFER, INCOMPLETE, WRITE_DISABLED. `ERROR;APPLY_PARTIAL;успешные_элементы;id;index` означает, что часть данных уже могла измениться; нельзя запускать процесс, пока не проверен/восстановлен согласованный набор. При потере ответа COMMIT прочитать данные обратно; не считать повторную отправку COMMIT гарантированной. Повтор того же SET в активной транзакции идемпотентен; конфликтующий SET для того же элемента отклоняется. Тайм-аут транзакции 10 с от BEGIN/SET; задаётся `setTimeout(ms)`.

## Буферизация и ограничения прототипа

`BEGIN` задаёт общее число **элементов**, не массивов; максимум 64. Записи копируются во внутренний буфер объекта, без обращения к write-функциям до COMMIT. На каждый элемент нужно 7 + длина ASCII-значения байт. Буфер 1024 байта на каждый объект, выделяется статически при создании объекта (если объект глобальный), без отдельного массива в скетче и без malloc/new. Другой размер можно задать единым флагом сборки `-DFLPROG_EXCHANGE_TRANSACTION_BUFFER_SIZE=2048` для всех единиц трансляции или изменить значение по умолчанию в заголовке библиотеки. Не задавать макрос только в .ino: размеры класса должны совпадать во всех единицах трансляции. Вместе с RX/TX-буферами это минимум 1408 байт RAM на объект при настройке по умолчанию, плюс служебные поля и стек; на малых AVR учитывать общий расход памяти. Например 10 названий по 32 байта UTF-8 и 20 int16 (до 6 байт ASCII) требуют не более 970 байт. При недостатке буфера SET отклоняется, активные массивы не меняются. Перед COMMIT все элементы повторно проверяются. Эта версия не требует полного набора массивов, не реализует откат при отказе функции записи, не гарантирует согласованность при конкурентном доступе и сбое питания. COMMIT применяет не более 64 элементов за один pool; операции с String могут выделять память. Ответ APPLIED означает применение к функциям записи (с проверкой чтением, если разрешено), а НЕ физическое завершение EEPROM. Для применения в автоклаве дополнительно требуется проверка полноты/согласованности рецептов, подтверждение долговременного сохранения и запрет старта до завершения/проверки обмена. При отказе до COMMIT старые значения не меняются. Не считать транспорт защитой от злонамеренного доступа.

Приём и отправка порциями (по умолчанию 32/16 байт за pool, настраивается). Не используются delay, ожидание строки, динамические контейнеры для протокола. UART Executor не сообщает размер свободного TX-буфера и результат записи, поэтому writeUart может блокироваться в конкретном Core; строгого realtime нет. Проверять длительность COMMIT и pool на целевом контроллере.

Для ручной отладки отправить `PING`, `INFO`, `DESCRIBE;0`, `GET;1;0` с LF. В каталоге tests есть вспомогательный скрипт для формирования CRC и HEX и тесты на ПК с имитацией UART. Они не заменяют Arduino-сборку и проверку на железе.
